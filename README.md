# Лабораторна робота №4 — варіант 12, Студент Б

Тема: генерація перестановок. Проєкт містить статичну бібліотеку, DLL, клієнт неявного зв'язування та клієнт явного зв'язування.

## Функції API

- `nextPermutation(int* values, int count)` — замінює масив наступною лексикографічною перестановкою. Повертає `1`, якщо наступна перестановка існує; `0`, якщо масив був останньою перестановкою (у такому разі масив переводиться до першої перестановки); `-1` для некоректного вводу.
- `heapPermutation(const int* values, int count, int* output, int outputCapacity)` — генерує всі перестановки алгоритмом Гіпа. Результат зберігається пласко: кожні `count` чисел утворюють одну перестановку. `outputCapacity` — місткість `output` у КІЛЬКОСТІ ЦІЛИХ ЧИСЕЛ. Повертає кількість записаних перестановок або `-1` у разі помилки.
- `generateAll(const int* values, int count, int* output, int outputCapacity)` — генерує всі перестановки в лексикографічному порядку. Формат виходу та значення повернення такі самі, як у `heapPermutation`.
- `permutationCount(int n)` — повертає `n!`; повертає `-1`, якщо `n < 0` або результат не вміщується в `int`. Для `n=0` повертає `1`.

## Обмеження й безпека

- Для функцій генерації `count` має бути від 1 до 10; для `nextPermutation` — від 1 до 100000.
- Для генерації всієї множини потрібно передати непорожні вказівники `values` і `output`, а також буфер щонайменше `count * count!` цілих чисел. Якщо буфер замалий, функція повертає `-1` і не записує частковий результат.
- Дублікати у вхідному масиві розглядаються як окремі позиції, тому однакові за значенням перестановки можуть повторюватися.
- Функції не зберігають передані вказівники після повернення та не виділяють пам'ять для користувача.
- `count` і місткість буфера повинні відповідати фактичному розміру масиву, на який вказує вказівник.

## Збірка (Windows + CMake + MinGW/MSYS2)

З кореневої папки проєкту виконайте:
```powershell
cmake -S . -B build -G "MinGW Makefiles"
cmake --build build
```
Якщо генератор MinGW Makefiles недоступний, можна використати генератор, який підтримує встановлений компілятор. Для запуску після збірки:
```powershell
.\build\StaticLibrary\StaticDemo.exe
.\build\ImplicitClient\ImplicitClient.exe
.\build\ExplicitClient\ExplicitClient.exe
```
DLL автоматично копіюється поруч із клієнтом явного зв'язування. Для неявного зв'язування CMake копіює DLL поруч із виконуваним файлом.

## Структура
- `StaticLibrary/` — STATIC-бібліотека та локальна тестова програма.
- `DynamicLibrary/` — SHARED-бібліотека, яка експортує C ABI.
- `ImplicitClient/` — клієнт, який підключає заголовок і лінкується з DLL через імпортну бібліотеку.
- `ExplicitClient/` — клієнт, який використовує тільки WinAPI `LoadLibrary`, `GetProcAddress`, `FreeLibrary`.
